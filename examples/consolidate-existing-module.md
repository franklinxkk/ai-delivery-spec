# 存量模块归并：少维护一套说法，不少一条业务条件

这是合成改写案例，不是执行报告。以下文件范围、权限和数值是本例题设，不作为其他项目默认政策。沿用团队文档；不要求另交条件台账。

## 改前：同一设备分组导入散在三处

**分组页**：管理员可用 CSV 导入分组。编码、名称必填；负责人选填。已有编码可跳过或覆盖。

**文件通用约定**：上传最多 5 MB、5,000 行，先预览再确认；任一行字段校验错误时整批不写入。

**旧补充段**：分组编码在当前机构内唯一。负责人填写时必须是当前机构的有效成员；留空不自动指定导入人。覆盖仅更新名称和负责人，编码和机构不可改。保存失败保留预览；取消不写入。导入不会给成员加设备权限。

另外，具备备份权限的人可导出停用分组；正常设备选择器只列启用分组。这两句不能因为都叫“分组范围”就合并成相同筛选条件。

## 改后：在设备分组模块连续读完

管理员在“设备分组→导入”选择 CSV，预览后确认；导入只维护分组，不分配设备权限。文件格式、大小、行数和预览流程沿用“文件通用约定”；本模块的编码和成员限制见下表。

| 字段 | 含义、输入及限制 |
|---|---|
| 编码 | 必填；在当前机构内唯一；新增时确定，覆盖时不可改 |
| 名称 | 必填；新增或覆盖时写入 |
| 负责人 | 选填；填写时须为当前机构有效成员；留空不指定导入人 |

| 元素/动作 | 条件与处理 | 结果与恢复 |
|---|---|---|
| 导入 | 管理员选择 CSV，按通用约定及本模块字段规则预览 | 不立即写分组；错误定位到行/字段 |
| 确认导入 | 预览通过，明确选择跳过或覆盖已有编码 | 整批提交；跳过不改原分组，覆盖仅改名称和负责人，不改编码或机构，不增加设备权限；保存失败保留预览 |
| 取消 | 尚未完成提交 | 不写入 |
| 导出备份 | 有备份权限 | 包含停用分组；设备选择器仍只显示启用分组 |

**验收场景：覆盖失败后恢复。** 前提：机构甲已有编码 G1 的分组，负责人为空；导入两行，其中 G1 的新负责人来自机构乙。操作：选覆盖并预览；把负责人改为甲的有效成员后重试确认。预期：首次指出 G1 负责人越界，整批无写入；修正后只更新 G1 的名称、负责人并新增另一行，不换机构、不加设备权限。另以负责人空白导入，保存后仍为空。

**验收场景：备份和使用范围不同。** 前提：甲有启用 G1、停用 G2，且操作者有备份权限。操作：导出备份并打开设备选择器。预期：备份含 G1/G2，选择器仅有 G1。不能为“统一口径”丢掉 G2 或使其可选。

## 表格服从实际对象，不创造“详情页”

另一份合成题设：连接列表维护数据库连接或HTTP接口，两类都可新增和编辑，只有各自配置弹窗，没有独立详情页。公共名称在列表显示；数据库需要主机、端口和数据库名，HTTP接口需要请求地址、方法及返回解析。下面只是裁剪方法，不添加认证或协议功能。

| 连接公共字段 | 新增／编辑 | 列表 |
|---|---|---|
| 名称 | 两类共用同一名称定义；在各自弹窗维护 | 显示保存后的名称 |
| 类型 | 新增选择；本例编辑不可换类型 | 数据库或HTTP接口 |

| 数据库配置弹窗 | 输入及结果 |
|---|---|
| 主机、端口、数据库名 | 按已有数据库连接合同填写；保存后用于该连接，不套用接口地址字段 |

| HTTP接口配置弹窗 | 输入及结果 |
|---|---|
| 请求地址、方法 | 按已有接口合同填写；由请求执行读取 |
| 返回解析 | 配置记录位置及字段；由该接口的结果解析读取 |

本片段不替代真实项目的长度、默认和必填定义；它示范共用字段只定义一次，子类型在同一模块就地分表。不为了表头齐全增加“详情”列，也不用“详情”含糊代指配置弹窗。如果另有运行记录，就以“运行记录”说明其结果字段。冷读者应能在交付原型找到对应位置；表格列数一致不能证明这种对应关系。

## 为什么可以删旧段，哪些不能删

唯一性落在编码行，负责人有效范围和不回填落在负责人行，覆盖边界及不加权落在确认动作，失败/取消结果各有位置；通用文件限制仍有明确引用。不是把三段原样拼成更长一段，也不是把细则换成“按权限处理”。如果同一主题实际条件冲突，先找有效决定；无法确定时保留具体分歧，不用更顺口的改写偷偷定政策。

稳定场景身份继续沿用；被归并的网页段落有外部引用时，旧锚点转到保留段落。动作表、状态图和验收分别解释行为、结构和判定，不要求消除它们之间一切重复词句；重点是不重复维护同一套完整规则。

## 原型也有两套处理器时

例如旧脚本登记“导入后立即写入”，新脚本覆盖为“预览→确认写入”。先查实际加载顺序、最后生效的动作和旧脚本是否还初始化分组目录。移除已被覆盖的旧导入弹窗与无消费者入口，保留仍被新处理器使用的目录初始化；不要整文件删除，也不要继续加第三层覆盖。

从真实入口新建一组、修改负责人为非默认值、保存关闭重开，再导入含非法负责人的两行，修正后确认。核对目录和消费者，而不只看成功提示；空负责人重开不能被初始化器补回导入人。保留有效数据与身份，不清空存储让测试变绿。

引用关系、锚点、表格和脚本语法可静态核对；业务条件保真与实际操作另核对。只因文字变短无需重跑所有已无影响的功能；处理器变更复验本路径及必要相邻消费者，报告沿用证据的基线和范围。

## 同一字段分期不同：合在原模块，不抹平差异

以下为脱敏改编的指标配置题设。P0 表示本期交付、P1 表示后期交付，不是缺陷等级。题设已批准，不再询问是否采用，也不作为其他产品的默认规则。

旧稿说“主体列默认第一列，保存后按绑定读取”；新决定是“P0 固定第一列，P1 才可选”。不能只在范围表加一句 P1，却保留本期可编辑控件、必填提示和测试预期。

**指标配置模块**：新增、编辑与复制创建使用同一表单；复制创建继承来源定义后可修改，生成独立停用指标，不改来源。编辑既有指标须满足本例已有的停用及维护权限条件。

| 字段 | P0：新增／编辑／复制创建 | P1 差异 | 保存及读取 |
|---|---|---|---|
| 数据源与 SQL | 可改；复制时继承 | 沿用 P0 | 更换来源或 SQL 后重检引用；不按相似名称自动换绑 |
| 统计主体列 | SQL 第一输出列，只读展示；无输出列不能保存 | 可从输出列选择并保存绑定 | P0 按当前 SQL 首列解释；P1 按保存绑定读取。不能拿 P1 的绑定规则覆盖 P0，也不能静默转换已有对象 |
| 指标值列 | 从实际输出列选择，必填；复制时继承，失效须修正 | 沿用 P0 | 保存重开后仍为所选列，执行时使用它而非固定第二列 |
| 维度标记 | 从 SQL 涉及源表的字段多选；可标记未返回字段 | 可编辑中文别名 | 标记不增改 SELECT 或分组。消费维度值仍须有 SQL 返回值或已登记关联；标记本身不是取值或授权证据 |

本例的保存约定是：失效引用定位到字段并保留输入，修正后才能保存；其他产品若允许存草稿，应分别写清草稿与执行条件，不能套用本例禁存政策。

**正例与反例**：SQL 返回“对象编号、学时、次数”，复制后将指标值列改为“次数”，保存重开及消费均使用次数，来源仍用学时。P0 主体仍是对象编号且不能选学时；P1 可选择并保存主体，但重排列后不按位置换绑。标记一个未返回维度，SQL 文本保持不变；删除其源表后不能悄悄删除标记或替换为同名字段。切回 P0，不因尚未填写 P1 中文别名阻断本期保存。

范围总表只列阶段与模块入口；这些字段差异及验收留在指标模块。规则引用处只展示有效解释，不再维护一套绑定表单。分期变更后同步当前入口、直达页、说明和验收，后期预览不冒充本期可交付。

## 两种相似改动，不能靠统一词句解决

以下也是合成题设；借鉴真实配置平台暴露的失败机制，不代表原项目运行结果。

| 场景及已定规则 | 容易误改 | 模块内如何写；怎样区分错误实现 |
|---|---|---|
| 数据平台的管理备份含停用项，消费目录只含启用项；归属关系按稳定标识绑定 | 两者复用消费过滤，备份漏项；换表后按字段位置重绑 | 在各动作写明对象范围与用途。含启停两项的备份均保留，消费只取启用项；换表后失效引用仍指向原对象并可修复。同名新表不能继承旧表授权 |
| 普通表单按钮可关联应用流程，但普通表单本身没有默认提交流程；流程表单才有默认流程 | 共用设计器导致所有表单都必配默认流程，或为去掉默认流程而删掉按钮关联能力 | 页面类型决定默认流程配置是否出现；按钮关联与应用级流程维护仍存在。普通页无默认流程也能保存、按钮能引用流程；转换为流程表单后才校验其必需默认流程 |
| 从历史设计复制一份独立草稿，保留当前草稿与旧部署；授权只看当前规则 | 复制时覆盖当前草稿，顺手恢复历史管理员权限或复制凭据 | 写清复制的是设计定义及引用，数据、凭据和管理授权不在复制范围。保存重开能区分两草稿；旧部署不变；没有当前发布权的人仍不能发布 |

遇到错误模型，例如用日期字段装带时区的完整时间，先核对模型、控件和比较条件，修正设计与错误样例；不能因样例无法通过校验就新增永久类型猜测或绕过发布校验。若存在真实旧数据，另外说明其影响和已授权处理，不能当作演示数据清空。

## 评审说“功能没有”，先核对能否完成任务

以下为合成审查题设，不是项目实测：设备报表的“导出”在选中已发布报表后出现；明细由脚本渲染。报表 A 当前已发布定义绑定接口 S1，新草稿改用 S2 尚未发布。报表 B 使用已保存的批次结果，约定保留历史；来源停用不撤销已存结果的读取许可。

| 观察或报告 | 判断与修订 | 最小可区分验证 |
|---|---|---|
| 静态HTML没找到导出按钮，所以导出缺失 | 未枚举不等于不存在。按角色、选择与发布前提，从实际入口查看；操作真的不可达再修入口 | 合法用户选择已发布 A，能导出；未发布项按已定条件不可导出，不为通过测试直接改状态 |
| 停用 S2 后 A 仍可读取，判来源校验失效 | 测错依赖：A 的有效定义仍是 S1。保持原预期，重新构造停用 S1 的反例；另查草稿生效后应采用哪个绑定 | 停用 S1 后按题设拒绝，恢复可读；B 仍可读已保存批次，不能把两种读取方式硬改成相同结果 |
| 从主页看没有报表，先访问报表页再回来才显示 | 若同一权限下已有正式报表，这是初始化/读取偏差；不把未初始化当零条业务事实 | 独立首次进入主页与先进入报表页的目录数量一致；有历史配置时重开不覆盖它，也不编造运行记录 |
| 无异常却打开必填派单空表单 | 缺少可处理对象时应按已定业务条件提供空态与下一步，不能让用户面对无法完成的表单 | 有异常可选择并派单；没有异常可查看检测入口，不能生成空派单 |

“匹配关系”这样的标签还需结合实际选项判断：若控制右侧重复键时展开还是拒绝，应叫“右侧重复键处理”，与连接类型分开。只有证实含义相同才统一名称，不能顺带改变数据规则或持久化标识。

产品里的“本地Mock暂不支持”与评审覆盖数放交付说明；用户需要的填写方法放附近帮助，错误要说清具体对象、条件和恢复入口。把长说明移走，不等于把拒绝原因一起藏掉。

本节使用现有字段、动作及验收组织，不再要求一张新的审查台账。修订时按对应模块回填；首次进入、已有配置、合法空态和失败恢复按本次风险选取，不机械要求每个小改动全跑。

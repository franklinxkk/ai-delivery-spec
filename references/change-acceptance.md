# 变更、交接反馈与验收

## 从一个有效决定开始

记录来源、授权、基线、前后变化与影响种子；继承已有决定。写入前核对版本，按主题合并并发变化，不以最后写入者胜出。

先定位权威定义及同义旧表述，按相同对象/条件写出一次动作前后结果，对照正文、字段/状态表、样例、AC及原型最终处理器；回填后从文件回读，不靠关键词存在判同步完成。历史版本或不同条件可合法不同，不能全局替换抹平。已决、已同步、已验证分别判断：正文待同步不使已决重新待批，旧验证不证明新内容。显示序号不是身份；换身份保留旧ID与替代关系。

## 找消费者并保留依据

从规则找写入者、读取者、指标、入口、事件/通知、旧数据、进行中流程、验收及接收者；说明直接/传递/仅回归/无影响的依赖依据。

推测消费者先记候选，核实或排除保留依据；核实不代表获准修改，未核实高影响依赖限制完成声明。

`impact` 仅沿已登记关系找候选，暴露缺种子、未解析关系和深度截断；命令见 [工具](stages.md)，输入见 [变更模板](templates/change-request-template.yaml)。复杂审计才用 change-package Schema；小改写在当前产物。迁移未评估可记录 unknown；已知需要迁移但方案未定，也可保留草稿，依赖它的批准/实施前再补方案与回退。旧格式继续可读，但批准、同步、验证等完成声明仍须有相应记录，不能把旧 false 或格式版本当授权。

已有对象如何处理须依授权决定；不能默认全部迁移或沿用。局部界面改动先留真实旧对象/草稿/进行中请求样本，改后核对新功能及这些样本仍遵循原规则，不能刷新演示数据掩盖回退。记录仍适用和失效的证据。反馈区分规格缺陷、实现偏差、过期测试、工具故障与新增范围；正确拒绝且无不当副作用才是负例通过，不改业务迁就测试。

## 证据按主张、范围、版本成立

| 证据 | 能证明 | 不能替代 |
|---|---|---|
| 静态检查 | 指定声明、引用、结构及可确定约束 | 自然语言业务真值和实际行为 |
| 语义评阅 | 指定对象的来源核对、反例及处置 | 运行验证；两模型一致也不是真值 |
| 处理器/模拟运行 | 给定输入下函数、Mock 存储及消费者的结果 | 用户可达入口、浏览器布局/拖拽、真实后端 |
| 浏览器原型 | 指定环境的操作、可见/Mock结果 | 真实接口、持久、并发与生产权限 |
| 真实系统 | 指定版本环境中的实际对象与结果 | 客户批准规则或验收签署 |
| 业务/客户确认 | 有权人在对应范围作出的决定或接受 | 实现已完成、范围外能力或上线 |

关键主张绑定范围、产物身份（文件哈希或可定位版本）、依赖、证据类型、环境、实际结果与位置。历史通过保留；依赖改变后当前适用性记待复验，无关变化有依据可沿用。普通 Word/HTML 复用现有记录，无须新建状态系统。未执行、缺来源、不适用分开。

断言数、唯一 AC 数和已验证行为分开；编号注释不算覆盖。按同一输入核对来源→PRD→原型实际操作→实现结果，检查对象/字段含义、状态、权限、口径、拒绝和副作用，允许有明确映射的不同命名。AC 前提须能独立造数或重置；删除对象使旧 AC 失效。声明可配置的规则，用改值前后样本验证各消费者响应及生效时点，不把所有阈值升级成配置平台。

复用 ARUN/EVD；真实验收保留 acceptance_ref、requirement_refs、result、actual_result、evidence_refs；execution_type 按实际区分静态、模拟、浏览器及联调，未知不猜，见 [验收模板](templates/acceptance-run-template.yaml)。一个 AC 的当前场景全部通过才计通过，拆到多个记录也一样；同一场景沿用 ARITEM id，独立场景用不同 id，失败/阻塞写实际结果。检查只提供本次适用记录；历史仍保留，不按时间或输入顺序自动取舍冲突结果。每个场景须有对应环境的执行证据，其他场景/环境不能补齐；实际执行与最终签署分别判断。同一 ARUN 编号不能由不同文件覆盖解释。本地证据可解析且不越出记录目录；远程链接或字符串不证明执行。

## 关闭

实际验证覆盖指定主路径及高价值拒绝/恢复；验收接受需相应有权签署。残留问题明确范围、责任及复议条件；有条件批准到期重新处理，不用条件措辞掩盖未完成的关键规则。

需求通过验收不等于已经发布。外部上线、运营和结果反馈只记录引用，必要时作为新来源或 CHG 返回；不由需求状态自动驱动生产操作。

# 变更、交接反馈与验收

## 从一个有效决定开始

记录来源、授权主题、当前基线、变化前后和影响种子。用户已有明确授权直接继承；编制新基线和复验旧证据不使其变成待批建议。写入前核对当前版本或摘要，发现并发变化按主题合并或返回待决，不选择最后写入者。

一条规则只改一个权威定义。页面、流程、原型说明、AC 与交接引用同步。显示序号变化不等于业务身份变化；需要替换身份时保存旧 ID 与替代关系，不改写历史。

## 找消费者并保留依据

从规则找到写入者、读取者、指标、操作入口、事件/通知、旧数据、进行中流程、验收与接收者。每项说明依赖链；区分直接、传递、仅回归和有理由的无影响。

将推测消费者记为候选；核实存在依赖后更新同一项及依据；已排除也保留理由。核实依赖不代表该修改已经获批。高影响候选未核实，限制依赖它的完成声明；不能让它因处于候选区就从风险分母消失。

`impact` 使用已登记关系给出路径和检索边界，不理解所有代码或自然语言。结果是候选清单，不能自动作为批准的修改列表；缺种子、未解析关系和深度截断必须暴露。复杂审计变更可沿用 [change-request-template.yaml](templates/change-request-template.yaml) 与 change-package Schema；小变更在当前产物写清即可。

已有对象如何处理须依授权决定；不能默认全部迁移或沿用。记录哪些证据仍适用、哪些失效以及谁接收新版本。工程反馈回链为规格缺陷、实现缺陷、来源失效或新增范围，不把它们混成同一种返工。

## 证据按主张、范围、版本成立

| 证据 | 能证明 | 不能替代 |
|---|---|---|
| 静态检查 | 指定声明、引用、结构及可确定约束 | 自然语言业务真值和实际行为 |
| 语义评阅 | 指定对象的来源核对、反例及处置 | 运行验证；两模型一致也不是真值 |
| 浏览器原型 | 指定环境的操作、可见/Mock结果 | 真实接口、持久、并发与生产权限 |
| 真实系统 | 指定版本环境中的实际对象与结果 | 客户批准规则或验收签署 |
| 业务/客户确认 | 有权人在对应范围作出的决定或接受 | 实现已完成、范围外能力或上线 |

每条关键主张绑定范围、基线、类型、环境/责任人、结果及证据位置。类型互补，不取最高等级替代全部主张。一个缺口只限制其依赖范围。未执行、缺来源、不适用分别记录。

已有 ARUN/EVD 继续使用；真实验收项保留 acceptance_ref、requirement_refs、result、actual_result 和 evidence_refs，见 [acceptance-run-template.yaml](templates/acceptance-run-template.yaml)。本地证据应可解析且不越出记录目录；远程引用可定位不代表已抓取验证。通过声明不能凭任意字符串证明。

## 关闭

实际验证覆盖指定主路径及高价值拒绝/恢复；验收接受需相应有权签署。残留问题明确范围、责任及复议条件；有条件批准到期重新处理，不用条件措辞掩盖未完成的关键规则。

需求通过验收不等于已经发布。外部上线、运营和结果反馈只记录引用，必要时作为新来源或 CHG 返回；不由需求状态自动驱动生产操作。

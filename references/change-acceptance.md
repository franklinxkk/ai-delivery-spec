# 变更、交接反馈与验收

## 从一个有效决定开始

记录来源、授权、基线、前后变化与影响种子；继承已有决定。写入前核对版本，按主题合并并发变化，不以最后写入者胜出。

先定位当前有效定义及同义旧表述，按相同对象/条件写出一次动作前后结果；在原模块及同一规则的实际消费者中原位同步正文、字段/状态表、样例、AC及原型最终处理器，不能在末尾追加“以此为准”留下冲突。写后在约定有效基线内回读同义旧表述及实际消费者，不靠关键词存在或命中数判同步完成。当前正文更新为有效规则；只有确需呈现历史时才保留旧文并明确其失效范围。历史版本或不同条件可合法不同，不能全局替换抹平。已决、已同步、已验证分别判断：正文待同步不使已决重新待批，旧验证不证明新内容。显示序号不是身份；换身份保留旧ID与替代关系。

## 找消费者并保留依据

从规则找写入者、读取者、指标、入口、事件、旧数据、进行中流程、验收及接收者；有据区分直接、传递、仅回归及无影响。同名功能可能分属不同编辑器、部署版本、预览和用户运行页。沿实际路由找到受影响者；共用处理器可复用计算验证，各自的入口和数据接线分别核对。推测先作候选；核实或排除保留依据，核实不等于获准修改，未核实高影响依赖限制完成声明。

`impact` 仅沿已登记关系找候选，暴露缺种子、未解析关系和深度截断；命令见 [工具](stages.md)，输入见 [变更模板](templates/change-request-template.yaml)。复杂审计才用 change-package Schema；小改写在当前产物。迁移未评估可记录 unknown；已知需要迁移但方案未定，也可保留草稿，依赖它的批准/实施前再补方案与回退。旧格式继续可读，但批准、同步、验证等完成声明仍须有相应记录，不能把旧 false 或格式版本当授权。

已有对象如何处理须依授权决定；不能默认全部迁移或沿用。修改前从原入口保存一个受影响的旧对象，再在同一份状态上打开修改后的页面，比较其实际读取结果；对象可用现有导出或测试工具保留，无须新台账。按原有字段含义读旧结果，不能用当前配置补写当时发生了什么，也不能刷新种子数据掩盖回退。记录仍适用和失效的证据。反馈先区分设计不足、规格缺失、已有规则执行违约、过期测试、工具故障与新增范围；先修对应问题，不因一次漏检追加通用规则或产品机制。严重度、未验证和缺材料是评审结论，不直接成为产品发布门槛。修守卫只落实当前有效规则对应的条件，不重新激活已取消的旧限制或遗留全量拒绝；复验对应拒绝与仍合法的路径。报缺陷前先核对对象ID、有效状态、输入、版本与观察位置；控件显示、业务状态和网络结果不一致时，查明差异再下结论。前提或观察方式错误则修测试，保留纠正依据，不算产品通过或失败；不能用另一处的“成功”提示替代目标结果。正确拒绝且无不当副作用才是负例通过，不改业务迁就测试。

## 证据按主张、范围、版本成立

| 证据 | 能证明 | 不能替代 |
|---|---|---|
| 静态检查 | 指定声明、引用、结构及可确定约束 | 自然语言业务真值和实际行为 |
| 语义评阅 | 指定对象的来源核对、反例及处置 | 运行验证；两模型一致也不是真值 |
| 处理器/模拟运行 | 给定输入下函数、Mock 存储及消费者的结果 | 用户可达入口、浏览器布局/拖拽、真实后端 |
| 浏览器原型 | 指定环境的操作、可见/Mock结果 | 真实接口、持久、并发与生产权限 |
| 真实系统 | 指定版本环境中的实际对象与结果 | 客户批准规则或验收签署 |
| 业务/客户确认 | 有权人在对应范围作出的决定或接受 | 实现已完成、范围外能力或上线 |

主张绑定范围、产物版本、依赖、证据类型、环境、结果及位置。业务依据与实现证据分别判断：有权人的明确决定或有效规格可规定应如何做，不证明已经实现；截图、源码或运行各只能支持其实际观察范围，不能把所有非实测材料都称为推断。保留历史通过；依赖改变待复验，无关变化可有据沿用。复用现有记录；未执行、缺来源、不适用分列。未拿到测试证据不能推出用户未测试；自动检查只能判断它实际可观察的条件。产品拦截须另有已授权规则与可取得的判定依据，不用自动推断或新增报备字段弥补观察缺失。

汇总前从拟写的完成声明反查原始记录。用已有脚本输出、操作轨迹、前后截图或可重放步骤，定位本版从哪一入口、以哪种身份、对哪个可辨认的对象做了什么，以及最终使用处实际读到什么。非默认值能把该对象与演示样例区分开。代造中间状态、切身份绕过阻断或直调处理器，单独计为定位问题的证据。输入准备与业务步骤区分，以用户要求的路径为准。只测到保存、下游结果不符或没有实际记录，就报告最后已证步骤和断点。接手其他 Agent 的“通过”同样要回查；关键证据相互矛盾或不足时，能重跑就从该入口复现，再下结论。按同一输入核对来源→PRD→原型实际操作→实现结果，检查对象/字段含义、状态、权限、口径、拒绝和副作用，允许有明确映射的不同命名。预期从有效来源独立推导，选少量能让错误实现产生不同结果或副作用的反例，见[可执行示例](../examples/configuration-to-consumption.md#executable-example)；不从待测代码反推答案。AC 前提须能独立造数或重置；删除对象使旧 AC 失效。声明可配置的规则，用改值前后样本验证受影响消费者响应及生效时点，不把所有阈值升级成配置平台。

复用 ARUN/EVD，字段见[验收模板](templates/acceptance-run-template.yaml)，execution_type按实际记录，未知不猜。每个AC当前适用场景全部通过才计通过；同场景保持ARITEM，独立场景另用ID，失败/阻塞写实际结果。检查只给本次适用记录，历史保留；不按时间或输入次序覆盖冲突。同一ARUN编号不得跨文件覆盖解释。各场景须有对应环境证据，其他场景/环境不能补齐；模板能保存预览只证明该搭建路径，不证明模板所命名行业的业务闭环。执行与签署分开。本地证据可解析且不越出记录目录；URL或字符串不证明执行。

## 关闭

行为与正文稳定后再生成截图、排版和分发副本；正文一致仍可能共同陈旧，核对当前内容与入口。局部变化只补验受影响区域，标明证据复用范围。

验证本次主路径及关键拒绝/恢复；验收需有权签署。残留问题明确范围、责任及复议条件；有条件批准到期重新处理，不用条件措辞掩盖未完成的关键规则。

需求通过验收不等于已经发布。外部上线、运营和结果反馈只记录引用，必要时作为新来源或 CHG 返回；不由需求状态自动驱动生产操作。

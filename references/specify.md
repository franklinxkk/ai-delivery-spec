# 最小充分业务规格

补清会产生不兼容业务选择的歧义；技术选择留给研发。机器通过不证明人能读懂。

## 沿实际任务组织

小改回填原处。正式PRD先写目标、范围、角色、模块主链和通用约定，再按页面/对象展开。指定单册时精确机器规则在同册尾部，不能依赖另一册才能开发；交付形式遵从用户约定。

复杂模块参考[配置到消费](../examples/configuration-to-consumption.md)；正式评审参考[工单样例](../examples/medium-review-handoff/requirement.md)。按需用[需求卡](templates/prd-light-template.md)或[PRD骨架](templates/unified-requirement-prd-template.md)，问题、方案与澄清可同册回填，不重复生成。

1. 从原始决定写清一个任务：谁对哪个对象，在什么状态/条件下操作，成功改变什么，拒绝保留什么，之后从哪继续。配置、执行和发布是不同对象。未定分支就地标出，不能靠状态名推断政策；例如尚未生效不因“不生效”就属于已过期。
2. 同一对象字段只定义一次，按相关新增/编辑/列表/详情场景对照含义、来源、类型/控件、必填、默认、校验与可改条件；不补齐无关CRUD。派生列说明生产者与消费者，不补手填。节点/子对象就地分表。
3. 动作归属页面任务，区分位置、作用、条件/权限、结果及恢复；按阅读需要合并列。把该动作的状态、数据和通知副作用一起写清，不让开发从其他章节猜。图补结构，文字保留硬条件。
4. 截图靠近对应界面，图讲主链，文字表格讲实现条件。核心规则不要藏在图里。列表、详情、配置和消费者的同一值应同源；同一动作多入口分别核对，不能以单条代替批量。
5. 验收用业务标题，写前提、操作、预期结果；ID辅助引用。共用规则一次定义，使用处标范围、差异和定位。读完模块须能确定输入、结果并造数，不能跨处猜关键步骤。稳定ID不因章节改名重编。

## 风险决定细节

| 内容 | 写清什么；用什么反例检验 |
|---|---|
| 状态/审批 | 分别核对对象与触发事件的变化及不变项、守卫和副作用；审核仅为前提时不等于发布，已授权自动发布不反改人工 |
| 退回/拒绝/失败 | 谁可改什么、从哪恢复、旧对象保留什么；失败不能只剩提示 |
| 指标/统计 | 对象、粒度/行数、公式/分母、时间/时区、过滤去重、来源、空零和时效；列数正确不证明粒度正确 |
| 权限/数据 | 操作者与执行/消费主体分别判定；最小合法范围能成功，越界/撤权拒绝且无额外写入 |
| 配置/旧对象 | 配置输入来源、提供者、时点及缺失行为；变更何时生效、旧实例如何处理 |
| 批量/异步/外部系统 | 提交前拒绝、调用已发出、明确失败、结果未知及正式成功凭据；不完整响应如何查询/对账；重试不得假定上次未写入 |
| 高后果AI写入 | 可信来源、可操作范围、确认/回退、拒绝；不越过用户授权 |

说清语义不等于新增配置。时间/时区、去重等固定规则不自动变下拉框或开关；只有已确定可维护的项才写入口、权限、校验和生效范围。未定政策不能藏进默认值。“待确认，但实现先按默认值执行”仍是在决定业务。区分用户明确授权的方案取舍、仅用于概念演示的假设和真正未决的执行分支；逐处检查正文、默认值和原型实际采用哪一种。

关键的“相同、有效、成功、完成”就地写参与字段及排除项。区分0、空、未采集、无权、失败和陈旧；不把来源有效当内容真实、相关性当授权或置信度当完成率。非功能目标写负载/资源/计时/失败统计条件；缺依据保留待决，不臆造SLA或把目标写成实测。

按对象、条件和有效版本合并正文、图、样例与原型，回填原处，不追加“以此为准”。历史/当前及配置/运行的合法差异保留映射。权威来自来源与授权；示例、领域包不能代定项目政策，未知只阻断依赖部分。

## 接收者冷读与行为验证

复杂交接由无作者讨论历史的接收者先只看约定交付包，定位操作、造正反数据并冻结首次理解与疑问；再读原始来源检查忠实性，不拿作者用例当唯一题目。来源本属于交付包时不剥离，两个结论分开记录。查业务理解、任务能否走完、视觉是否可读三件事，回填需要猜的选择。AI接收不能冒称真人验收，作者自检也不能称独立冷读。

先想一个貌似合理的错误实现，再用能区分它的数据检验。负例只改待测条件，其他前提合法；检查拒绝原因及状态、数据、通知副作用。配置从真实入口→保存→关闭重开→执行→消费者读取→修改→旧实例核对，按实际提供环节走；非默认值、边界及相关组合应改变真实结果。已有导入导出才查保真，不自行加功能。预置示例或隐藏函数参数不证明用户可配置。

分别记录首次交付漏出的问题、修订回退和未决业务选择；最后修好不抹去首次遗漏。检查正文与原型都遵循来源，不能只证明二者一致。

复杂交接可在模块入口索引起点、已定/待决、依赖和验收，引用既有规则，不复制字段、API/DDL。沿用工程约定，缺失且影响实现才澄清。

交接就地分清已定、待决影响与技术选择。未知影响动作时限定可实施分支与守卫，不放行待定分支或替未定政策作决定；显式列未知不等于可实施。正文、截图、状态及验收按最终产物复验。Markdown不证明已复刻Word版式，Word/PDF须实际渲染。静态、模拟、浏览器、后端和业务签署分别报告；小改不强制全角色或全量冷读。

## 可选机器声明

日常不强制元数据或台账；检查见[工具](stages.md)，草稿用specify，基线用baseline。DEC/UNK可在正文维护；关闭未知须有resolution_ref/source_refs，风险接受保留授权范围。semantic_reviews按Schema记录并复用ARUN/EVD，不把not_run改pass。

GAP需判明缺决定、合理差异或误报，不为变绿编造政策。机器契约联调可用[check-examples](stages.md#契约样例校验)，不替代语义和运行验证。

用例区分必需业务结果、允许变化的实现投影和观察层级。业务等价不要求字段投影相同，技术选择不豁免重复写入。见[异步写入反例](../examples/configuration-to-consumption.md#异步写入与真实接收)。

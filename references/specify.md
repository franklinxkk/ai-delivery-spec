# 最小充分业务规格

不让实施者补猜关键业务选择。用业务语言表达；一条事实只维护一次，其他页面、流程和机器交接同源展开，不分别改写。

## 从当前改变纵向写清

小改只写必要差异；正式 PRD 或多模块交接按“目标/范围与角色入口 → 系统模块关系与主链 → 模块完整说明 → 共用约束与工程索引”组织。每个模块就近展开入口/前提、主与异常流程、页面/字段/动作、状态/权限/数据结果、下游、验收和待决，按实际内容裁剪；不能用全局横向表格代替模块。见 [模块成品](../examples/medium-review-handoff/requirement.md)。

产品能看懂任务与边界；前端能确定可编辑性、条件、反馈和恢复；后端能找到输入权威、对象/版本、守卫与副作用；测试有前置数据、步骤和结果。共用事实一处维护，在使用位置动态展开或给有含义的摘要与具名链接，不能只放 ID 让人跨表拼接。术语就近解释；概览必须带关键例外，如管理员也不能自审。

标题和分发格式按用途选择，不定章节数；确需多投影才用 Product Truth。机器声明与大索引避开主阅读面；`project-human` 可去除机器头，但正文须已承接有效决定与未知。分发件注明源版本，不能反向覆盖来源。

可从 [需求卡](templates/prd-light-template.md) 或 [统一规格](templates/unified-requirement-prd-template.md) 开始；模板是编辑起点，不适用部分可删除。数据库、框架、端点或精确阈值只有构成已授权业务/集成约束才进入规格，不能为填空发明。

## 按风险补足，不按规模升级

| 触发内容 | 必要业务约定与反例 |
|---|---|
| 状态/审批 | 按源状态→触发者/动作→守卫→目标状态/副作用写转移；逐个核对已授权分支、终态及拒绝恢复，未决不补猜；通过仅为发布前提时不得自动发布 |
| 指标/统计 | 对象、公式与分子分母、时间/时区、过滤/去重、权威源、空零与时效；用边界数据检查 AND/OR、分母和快照 |
| 拒绝/退回/失败 | 谁还能修改什么、从哪重提、旧对象保留什么；拒绝后有真实下一步而非只有提示 |
| 可空或陈旧数据 | 区分零、空、未采集、无权、失败和过期；已决显示可继承，不猜未知的业务含义 |
| 权限/隐私 | 主体、对象、动作和数据范围；UI隐藏不证明授权；按实际可达路径检查深链、撤权、批量 |
| 身份/已有规则变更 | 区分显示序号与稳定身份，查读写、计数、旧对象、别名和失效证据 |
| 外部系统/批量/异步 | 生产者/消费者、匹配/版本、时效、重复/乱序/部分成功与恢复；区分请求身份、业务对象身份和写入后生成的记录 ID |
| 高后果 AI 写入 | 数据与指令来源、可操作范围、确认/回退、拒绝及异常；工具执行不越过用户授权 |

标签仅辅助索引，正文有风险仍需审查。高影响规则逐条查，其他抽样并说明未覆盖范围；接收者一致也需核对来源和反例。

关键守卫、派生值和权限范围须能找到输入的含义、来源/版本、由谁在何时提供，以及缺失时的行为。例如“没有待办才能提交”需有待办的真实来源；“按约定分期”不能由研发自定一期。沿用现有引用，不为所有名词新建表。性能、容量、隐私、留存、无障碍等影响业务可用或验收时，明确适用场景、已决约束和测量条件；缺少目标值列待决，不臆造 SLA。

正文抽查先找“两个实施者会在哪里作出不同业务选择”，再找同主题、同版本、同对象的明确答案。审批状态本身不自动要求退回恢复；只有实际出现拒绝、退回、失败或写入副作用才查对应恢复。AI 只读/草稿与自动写入分别判断；置信度不等于完成率，检索相关性不等于授权，来源凭证有效不等于内容为真。领域包只能提示检查维度，不能替项目决定取值、阈值和政策。

用户明确要求“审核通过后自动发布”时，应继承自动发布决定，核实必要的权限、触发和失败边界；不能借“审批不等于发布”的检查原则反改为人工发布或重新询问已决问题。

业务审批与需求评审分别记录，需求确认不代表业务对象获批。

页面标签、存储枚举、接口与决定不一致时，先核对对象、版本和表达层：筛选页签可能汇总多个状态。明确对应关系、适用权威与裁决来源；无法裁决列未知，不能按多数票、最新文件或 DDL 自动胜出。变更后复核正文、字典、转移、验收及标注中的同一事实，尤其保留此前修复的反向分支。

## 可选机器声明

日常文本不强制 frontmatter。`gate --profile prd` 可用 artifact_mode、baseline_version、requirement_ids、risk_facets 定位；DEC/UNK 可在正文维护，不另抄台账。草稿检查选 `--stage specify`，基线选 baseline；缺声明不能自动补成已确认。

声明经过结构检查不证明授权真实性。unknowns 的关闭绑定 resolution_ref/source_refs；风险接受另写其授权与当前执行边界，不能只改成 closed。需要审查记录时，在同一规格或现有 ARUN/EVD 中保留类别、对象范围、来源、版本、评阅者、结果、证据。支持类别为 state_authority、metric_definition、recovery、null_stale、permission_boundary、change_propagation；未执行用 not_run，不适用说明理由。

未知可只维护正文表，支持 `待关闭（open）` 与 `需求基线（baseline）`；重复声明须一致。授权需打开来源核对人、原话、主题、范围和时间，脚本不能鉴伪。

`semantic_reviews` 的 pass 需要 scope_refs、source_refs、reviewer、baseline_version 和 evidence_ref；not_applicable 需范围、理由、评阅者及当前版本。检查范围由 --scope-ref 或 requirement_ids/scope_refs 指定；一个对象的通过不能覆盖另一个对象。正文疑点独立于记录检查：核实是缺决定、适用范围不同还是工具误报，再修改规则或在原处记录理由，不能只补一个 pass。外部实际结果使用 [验收合同](change-acceptance.md)。

## 交接的充分性

复杂或正式交接，让无讨论历史的接收方复述主路径、恢复、数据权威和未决，或完成小型实施/测试。同一输入在来源、规则、AC、标注与实现中应有相容结果；预期反查决定。测试数据可内联或引用，技术选型不计规格缺失。

关键守卫需有判据，不能只预置状态掩盖事实如何产生。已决封闭集合可拒绝集合外动作，未裁决分支仍待决。反例须让正确与相似错误实现产生不同结果。负例只改变待测条件，其他前提合法，检查拒绝原因与状态/数据/通知副作用；有状态用例独立建前提或重置。HTTP 码仅用于真实接口合同。

小改无须全角色报告。交接写清可实施、仅可演示及受阻的具体能力和依赖，复用 DEC/UNK，不增状态台账。一个缺口不阻断无关能力；“可开发/验收完成”需该范围的决定、来源和证据。

# 最小充分业务规格

补清会产生不兼容业务选择的歧义；框架、存储等技术选择留给研发。编号齐全或机器通过不证明人能读懂。

## 沿实际任务组织

小改回填原处。正式PRD先写目标、范围、角色、模块主链和通用约定，再按页面/对象展开。指定单册时精确机器规则在同册尾部，不能依赖另一册才能开发；交付形式遵从用户约定。

复杂模块先读[配置到消费成品](../examples/configuration-to-consumption.md)，双态评审再读[维修工单成品](../examples/medium-review-handoff/requirement.md)。按需用[需求卡](templates/prd-light-template.md)或[PRD骨架](templates/unified-requirement-prd-template.md)。问题、方案、澄清可同册分段承载；收敛回填，不重复维护或逐份生成。

1. 用实例串起入口、配置、保存、生效与失败恢复。任务配置、运行批次和发布结果是不同对象，不能画成一条状态轴。
2. 同一对象字段只定义一次，默认用七列字段表对照新增/编辑/列表/详情，写含义、来源、类型/控件、必填、默认、校验与可改条件；删无关场景列，不补齐CRUD。派生列说明生产者与消费者，不补手填。节点/子对象就地分表。
3. 动作归属页面任务。复杂页面用六列元素表区分位置、名称、作用、结果、条件/恢复与权限；简单动作可合并列。写入、事件、状态、拒绝与取消就近写；独立计算/状态表只补新增信息，不重抄动作。图补结构，文字保留硬条件。
4. 截图靠近对应界面，图讲主链，文字表格讲实现条件。核心规则不要藏在图里。列表、详情、配置和消费者的同一值应同源；同一动作多入口分别核对，不能以单条代替批量。
5. 验收用业务标题，写前提、操作、预期结果；ID辅助引用。共用规则一次定义，使用处标范围、差异和定位。读完模块须能确定输入、结果并造数，不能跨处猜关键步骤。稳定ID不因章节改名重编。

## 风险决定细节

| 内容 | 写清什么；用什么反例检验 |
|---|---|
| 状态/审批 | 分别核对对象与触发事件的变化及不变项、守卫和副作用；审核仅为前提时不等于发布，已授权自动发布不反改人工 |
| 退回/拒绝/失败 | 谁可改什么、从哪恢复、旧对象保留什么；失败不能只剩提示 |
| 指标/统计 | 对象、粒度/行数、公式/分母、时间/时区、过滤去重、来源、空零和时效；列数正确不证明粒度正确 |
| 权限/数据 | 操作者与执行/消费主体分别判定；最小合法范围能成功，越界/撤权拒绝且无额外写入 |
| 配置/旧对象 | 配置输入来源、提供者、时点及缺失行为；变更何时生效、旧实例如何处理 |
| 批量/异步/外部系统 | 提交前拒绝、调用已发出、明确失败、结果未知及正式成功凭据；不完整响应如何查询/对账；重试不得假定上次未写入 |
| 高后果AI写入 | 可信来源、可操作范围、确认/回退、拒绝；不越过用户授权 |

说清语义不等于新增配置。时间/时区、去重等固定规则不自动变下拉框或开关；只有已确定可维护的项才写入口、权限、校验和生效范围。未定政策不能藏进默认值。

关键的“相同、有效、成功、完成”就地写参与字段及排除项。区分0、空、未采集、无权、失败和陈旧；不把来源有效当内容真实、相关性当授权或置信度当完成率。非功能目标写负载/资源/计时/失败统计条件；缺依据保留待决，不臆造SLA或把目标写成实测。

合并稿以同一对象、条件和有效版本对照正文、状态、样例、原型和AC，回填原处，不追加“以此为准”。合法的历史/当前、配置/运行差异保留映射。权威来自核实的来源与授权，不来自多数、文件新旧或DDL。示例和领域包只借组织与检验方法，不带入项目政策；未知只阻断依赖范围。

## 接收者冷读与行为验证

复杂交接按风险选任务，让无讨论历史的接收者凭交付件定位原型、复述输入输出、守卫并造正反数据。预先记录题目与独立预期，作者不补答案；回填必须猜的选择。模型冷读不冒称真人接收，局部通过不代表整册通过。

先想一个貌似合理的错误实现，再用能区分它的数据检验。负例只改待测条件，其他前提合法；检查拒绝原因及状态、数据、通知副作用。配置从真实入口→保存→关闭重开→执行→消费者读取→修改→旧实例核对，按实际提供环节走；非默认值、边界及相关组合应改变真实结果。已有导入导出才查保真，不自行加功能。预置示例或隐藏函数参数不证明用户可配置。

按需记录须猜选择、同条件冲突与证据夸大的数量，只定位问题，不作质量分或门禁。来源、原型、用例也可能一起错，关键结果仍用业务依据与独立预期核验。

交接就地分清已定、待决影响与技术选择。未知影响动作时限定可实施分支与守卫，不放行待定分支或替未定政策作决定；显式列未知不等于可实施。正文、截图、状态及验收按最终产物复验。Markdown不证明已复刻Word版式，Word/PDF须实际渲染。静态、模拟、浏览器、后端和业务签署分别报告；小改不强制全角色或全量冷读。

## 可选机器声明

日常文字不强制frontmatter或台账；确需检查时见[工具](stages.md)与Schema，草稿用specify，基线用baseline。缺授权不能补成已确认；DEC/UNK可在正文维护。关闭未知须有resolution_ref/source_refs，风险接受保留授权范围；semantic_reviews按Schema记录，复用ARUN/EVD，不把not_run改pass。

正文GAP未命中不证明通过；疑点判定为缺决定、合理差异或误报，不能为变绿编造来源和政策。已有机器契约联调时用[check-examples](stages.md#契约样例校验)校验权威Schema的正反例，不能代替自然语言语义与运行验证。

用例区分必需业务结果、允许变化的实现投影和观察层级。业务等价不要求字段投影相同，技术选择不豁免重复写入。见[异步写入反例](../examples/configuration-to-consumption.md#异步写入与真实接收)。

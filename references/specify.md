# 最小充分业务规格

不让实施者补猜关键业务选择。用业务语言表达；一条事实只维护一次，其他页面、流程和机器交接同源展开，不分别改写。

## 从当前改变纵向写清

小改只写必要差异；正式 PRD 或多模块交接按“目标/范围与角色入口 → 系统模块关系与主链 → 模块完整说明 → 共用约束与工程索引”组织。每个模块就近展开入口/前提、主与异常流程、页面/字段/动作、状态/权限/数据结果、下游、验收和待决，按实际内容裁剪；不能用全局横向表格代替模块。见 [模块成品](../examples/medium-review-handoff/requirement.md)。

从一个业务实例核对模块边界：谁从哪进入，在哪配置，哪个系统写入事实，下游凭什么对象/版本接续。菜单位置不等于系统职责；配置对象、运行实例、待办投影分别说明。产品读懂任务；前端确定字段/反馈/恢复；后端确定输入权威/守卫/副作用；测试能独立造数。共用事实就近展开或摘要链接，不能让读者跨表拼接；术语和关键例外就近解释。

标题用业务任务名；ID仅为真实引用/持续跟踪分配，放引用列或工程索引，不随改名重编，不另填 `referenced_by`。`project-human` 只去机器头，不改善正文；分发件注明源版本，不反向覆盖来源。

按需选 [需求卡](templates/prd-light-template.md) 或 [统一规格](templates/unified-requirement-prd-template.md)，删不适用项。业务字段的含义、来源、必填/空值、默认行为及关系属于需求；存储类型、框架、端点由研发选择，除非已有集成约束。两者不能混为“实现细节”。

## 按风险补足，不按规模升级

| 触发内容 | 必要业务约定与反例 |
|---|---|
| 状态/审批 | 按源状态→触发者/动作→守卫→目标状态/副作用写转移；逐个核对已授权分支、终态及拒绝恢复，未决不补猜；通过仅为发布前提时不得自动发布 |
| 指标/统计 | 对象、公式与分子分母、时间/时区、过滤/去重、权威源、空零与时效；用边界数据检查 AND/OR、分母和快照 |
| 拒绝/退回/失败 | 谁还能修改什么、从哪重提、旧对象保留什么；拒绝后有真实下一步而非只有提示 |
| 可空或陈旧数据 | 区分零、空、未采集、无权、失败和过期；已决显示可继承，不猜未知的业务含义 |
| 权限/隐私 | 主体、对象、动作和数据范围；UI隐藏不证明授权；按实际可达路径检查深链、撤权、批量 |
| 身份/已有规则变更 | 区分显示序号与稳定身份，查读写、计数、旧对象、别名和失效证据 |
| 外部系统/批量/异步 | 生产者/消费者、匹配/版本、时效、重复/乱序/部分成功与恢复；区分请求身份、业务对象身份和写入后生成的记录 ID |
| 高后果 AI 写入 | 数据与指令来源、可操作范围、确认/回退、拒绝及异常；工具执行不越过用户授权 |

标签仅辅助索引，正文有风险仍需审查。高影响规则逐条查，其他抽样并说明未覆盖范围；接收者一致也需核对来源和反例。

守卫、派生值和权限范围要有输入来源/版本、提供者/时点和缺失行为；不能预置“可提交”掩盖判据。沿用引用，不为所有名词建表。非功能约束影响验收时写适用负载、资源、计时和失败统计条件；缺目标列待决，不臆造 SLA，不把目标记成实测。

正文抽查先找“两个实施者会在哪里作出不同业务选择”，再找同主题、同版本、同对象的明确答案。审批状态本身不自动要求退回恢复；只有实际出现拒绝、退回、失败或写入副作用才查对应恢复。AI 只读/草稿与自动写入分别判断；置信度不等于完成率，检索相关性不等于授权，来源凭证有效不等于内容为真。领域包只能提示检查维度，不能替项目决定取值、阈值和政策。

已授权自动发布就继承该决定并核对权限与失败边界，不反改人工发布或重复询问。

业务审批与需求评审分别记录，需求确认不代表业务对象获批。

合并稿按同一对象/版本/条件对照正文、字典、状态表、样例、AC和标注；汇总页签与旧版本别名可合法不同，须写映射。矛盾回填原条目，不能再追加一段“以此为准”。权威取决于来源和授权，不按多数、文件新旧或DDL裁决；保留修好的反向分支。

## 可选机器声明

日常文本不强制 frontmatter。`gate --profile prd` 可用 artifact_mode、baseline_version、requirement_ids、risk_facets 定位；DEC/UNK 可在正文维护，不另抄台账。草稿检查选 `--stage specify`，基线选 baseline；缺声明不能自动补成已确认。

结构检查不鉴伪授权。unknowns 关闭绑定 resolution_ref/source_refs；风险接受保留授权和执行边界。需审查记录时复用原文/ARUN/EVD，写类别、范围、来源、版本、评阅者、结果与证据。类别：state_authority、metric_definition、recovery、null_stale、permission_boundary、change_propagation；未执行 not_run，不适用说明理由。

未知可只维护正文表，支持 `待关闭（open）` 与 `需求基线（baseline）`；重复声明须一致。授权需打开来源核对人、原话、主题、范围和时间，脚本不能鉴伪。

`semantic_reviews` 的 pass 需 scope_refs、source_refs、reviewer、baseline_version、evidence_ref；not_applicable 需范围、理由、评阅者及当前版本。--scope-ref 或 requirement_ids/scope_refs 限定范围，一个对象不覆盖另一个。正文疑点仍须裁定为缺决定、范围不同或误报，不能补 pass 消除；实际结果见 [验收合同](change-acceptance.md)。

## 交接的充分性

复杂交接选一个模块，让无讨论历史的接收方仅凭正文写出页面行为、服务守卫和测试数据；记录他必须猜的业务选择，回填该处。可由独立模型执行，但不冒称真人接收。框架/索引等技术选择不是缺口；未做冷读就说明未验证。来源、规则、AC、标注与实现的同一输入应有相容结果，预期反查决定。

先构造一个貌似合理的错误实现，再选能区分它的反例；按风险检查角色兼任、版本变化、源成功而下游失败等组合，不穷举全部组合。负例只改待测条件，其他前提合法；断言拒绝原因及状态/数据/通知副作用，独立造数或重置。已决封闭集合可拒绝外部动作，未知仍待决；HTTP码仅用于真实接口合同。

配置型平台须验证“配置产生行为”：从空白或明确继承模板经过模型→表单→权限→流程→测试/批准→发布→使用→数据回流，再改变一个关键配置，核对保存重开、生效时点和旧实例。只走已承诺能力，未提供某环节则说明边界；预置示例跑通不证明可配置，未运行不能写通过。公开导入/导出才检查往返保真。

AI Coding所用Schema/配置示例须实际校验合法及错类型、缺必填等负样例；语法合法不等于表达了约束。复用权威Schema而非再手抄一套，按需用 [check-examples](stages.md#契约样例校验)；它不替代语义审查或行为测试。

交接就地说明已定业务、待决影响、研发可自行选择的实现；复用 DEC/UNK，不另建表。读者必须能从业务说明答出关键行为，不能靠反读源码。显式登记未知防止猜测，但不等于该能力可实施；缺口只阻断依赖范围。小改无须全角色报告。

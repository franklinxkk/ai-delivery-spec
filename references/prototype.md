# 可操作原型

沿用当前规格、基线与已有设计原件；需要定位团队约定时再查[团队资料](team-customization.md)。单HTML可分本地CSS/JS编辑再合成；保留原布局、密度、组件及代表数据，不移植样例审美。

## 范围与路径

盘点受影响页面、入口、处理器、对象、身份、状态及Mock边界。大文件先索引再按路径读；机器盘点可用 `scripts/extract_interaction_ledger.py` 或 [Stage 0 模板](templates/stage0-inventory-template.yaml)，轻改简记即可。

先走完一条用户任务再扩页面，核对身份、状态及最终结果。只读查询从汇总或搜索定位正确对象、查看明细，再返回继续处理；对已有或本次要求的筛选，检查条件可见、可改、可清除；有汇总下钻时核对条件、统计范围、列表与分页一致，不为验证补造保存动作。写入任务按实际环节走到保存、重开及下游读取或计算。配置验证见[配置产生行为](specify.md#接收者冷读与行为验证)。

## 产品与评审

绘制前继承既定演示方式。有角色差异且尚无约定时，让操作者选全权限探索或按角色体验。全权限探索时，评审人用同一演示身份走完功能，仍选择正确的业务对象、企业及合法状态。正式权限在[规格](specify.md)中按角色和动作说明，展示开放不能证明权限控制正确。按角色体验时，分别走合法和拒绝路径；业务要求的真实人员交接要保留。

默认可操作产品态，参考[同源纯产品样例](../examples/medium-review-handoff/product-prototype.html)。双态按 [review-workspace.md](review-workspace.md)，先业务与就近说明，再组装映射。交接按 [context.md](context.md)，不复制业务规则。

两态共用产品页面、状态、动作；评审选择/高亮/展开不得改业务数据。业务审批与需求评审分别建模。主阅读面说业务，稳定 ID、枚举和技术追溯收起。无 UI 的系统规则不伪造按钮；候选不自动成为正式点。辅助评审功能仅启用时承担对应合同。

产品设计评审委员会按受影响范围检查四个视角：业务任务能完成，操作者没有重复填写或确认系统已有事实；交互与无障碍可用；视觉与组件语义一致；工程加载与状态更新合理。沿用已确认的设计体系，按需用可用的专业资源；这是检查视角，不强制四个 Agent、固定外部 Skill 或新的审批等待。在常用窗口实际打开关键状态，查看画面里的布局、遮挡和滚动，再用正常点击核对结果。脚本强制点击或批量生成截图只证明它实际执行的部分。

就近说明可用组件附加，不复制教学业务。正式R0/R1才承担工作台合同，附加说明不冒称正式工作台。单HTML需核对依赖，不把预览壳当单文件。

## 没有团队设计原件时

先确定页面任务和类型：列表呈现可比较的记录及行内动作，详情呈现当前对象，配置页按操作顺序组织输入；不能把选一个对象的下拉框冒称列表。优先使用一致的主次按钮、间距、必填与状态表达，不为“标准”强上某个组件库或评审壳。无数据、筛选为空、无权、加载失败分别提供其已有业务所需的反馈和下一步，不新增无依据的操作。桌面常用宽度核对表格、长表单及弹层；主页面与关键弹层的实际截图靠近规格，截图不足以证明点击或业务结果。

## 交互约定

先在已认可的面板上完成真实编辑任务。设置项用一个具体问题取舍：谁会因哪两种实际用途选择不同值，使用结果如何不同？同一种结果沿用默认值或已有样式。排版分组由阅读顺序决定；切换同级内容用页签，顺序填写用分节，执行动作用按钮。检查从第一项滚到最后一项是否仍能看见并编辑内容。只核对受影响路径。

按任务排布筛选、动作、列表及编辑；测试、实现和审查说明进文档或评审层。统一多个子页时，对齐页内的当前标题、导航、筛选、主动作与内容层次；共享外壳不能替代逐页核对，也不把首页汇总和无关新建动作机械复制到每页。表格、图谱等保留符合各自任务的内容结构。填法和影响就近帮助，支持键盘；阻断原因及恢复入口不只靠短暂提示。沿用主次按钮、状态和必填提示，常用宽度检查换行、宽表及弹层。重复配置按常用数量编辑中间、末项，核对滚动后的列义、定位和输入保留；见[长列表反例](../examples/configuration-to-consumption.md#repeated-config)，不固定尺寸或条数。

字段共用定义：输入有维护入口，派生值有来源。换来源先标出失效引用；未约定自动清除时保留供修正，仍有效的输入不丢失。草稿、保存与执行分别按项目规则校验，不能因可留草稿就允许执行。节点消费真实上游字段，以稳定标识而非名称或列位置区分。

每个业务动作须有真实处理器、允许条件、结果和失败反馈。普通导航不强绑业务 AC。JS 模板保留完整字面量 `data-action`，不能删除锚点规避检查；静态候选可枚举不代表运行时可达，须从真实入口打开验证。

首次直达与带已有数据重开分别核对；无对象、未初始化、无权与读取失败不能混作正常空态。受影响页签、环境或模式须逐个打开，核对内容、当前对象和可继续的操作；有页签或容器不等于内容已实现。多个模式应有可解释、可观察的对象/版本、权限、数据或操作差异；若仅名称不同，指出重复并按授权简化，不默认删除有业务差异的路径。新窗口与深链接也须检查身份、状态及结果，不能只验证打开成功。

各入口共用当前有效的取数、动作条件及状态转换；修守卫不重新激活已取消的旧限制或遗留全量拒绝。提交时重检状态、权限与成功凭据：条件失效拒绝且无新写入，仍合法则可完成，关闭不一概禁止操作。提醒、处置、回执分属不同维度时不合并状态。名称不是身份；当前身份约束提示、详情、草稿及未决请求。DOM投影当前状态，不另存业务副本。

- 同一动作的行内、详情、批量等实际入口按相同对象/状态/身份核对守卫与副作用；差异须有业务依据。修改字段后立即点击提交，检查失焦/重绘是否吞掉第一次点击；再关闭重开并读下游，防局部成功被另一缓存覆盖。记录实际写入对象，公开 Mock 边界。
- 选择控件时先用一个边界合法输入试填，再提交、重开读取控件的value及最终结果。例如已定“去首尾空白后计长度”时，原始输入长度可能更长；maxlength在提交前就截短，不能代替规范化后的校验。含引号、换行按当前字段许可取样，不靠HTML拼接改变值。失败保留输入，其他校验沿用业务条件。
- 优先事件委托和 `data-*`；父处理器排除输入控件，保留光标时不整片重建。操作迟缓先查重复渲染、监听及加载，再按交付形式拆分，不臆定性能阈值或删功能。浮层带当前对象，从真实入口打开。
- 外部 iframe 仅用于真实集成，说明来源/信任边界/失败退路；可打开不等于集成验证。

未决在评审层引用原 UNK 和影响；产品只实现已授权边界，不代定冻结指标、取最新或自动补偿。负责人缺失写未指定。

## 验证与完成

按来源反查角色、页面、状态、数据及视觉，可用 PAGE-CONTRACT；变化在原模块及同一规则的实际消费者中原位同步，不能末尾追加“以此为准”保留冲突。获准删除须同步入口/处理器与依据。

跨模块主链、受守卫状态、多系统数据流分别按需画最小流程/状态/数据图，与正文及运行对象一致；简单 CRUD 不堆图。

从来源清点覆盖，不由 marker 或控件数量决定。逐项配置核验时，给受测项选择适合其含义的合法非默认输入，观察应改变的消费者结果及应保持的值；不把所有数字输入填同一个值，也不以控件 value 或 DOM 变化代替预期结果。保存、应用、删除等动作按实际任务核对，不能只遍历 input/select。批量脚本可发现线索，未观察消费的项仍待验证；共享实现可复用证据，但明确逐项核验时须定位每项适用结果，差异分支不能省略。用少量能区分错误实现的反例，保留合法与拒绝后恢复路径，见[配置和预设反例](../examples/configuration-to-consumption.md#configuration-result)。浏览器验证提交、重开及后续读取，入口报错先修；调函数仅算模拟，截图核对正文与遮挡。保持详情/浮层打开后切换身份或对象，再提交；同名不同ID仍独立。异步刷新查询原请求再测旧页，不抹掉历史编号；禁用按钮不证明旧请求被拒。记录动作、预期、前后数据及文件，改后复验，未执行/阻塞不记通过。

正式评审带实际需求基线；命令与层级说明见[原型诊断](troubleshooting.md#原型机器锚点与诊断)。

原型关联需求版本，区分业务、演示与评审工具；工具不成为业务需求，新行为仍需授权。

# 宿主与接收工具

只有指定模型、Coding Agent 或外部协作工具接收产物时读取。本 Skill 不依赖某一模型的固定提示词技巧；接收合同跟随任务和真实工具能力。

## 共用交接

明确本次范围、当前有效决定、来源版本、关键规则与稳定引用、验收、未知和执行边界。已有 PRD/卡片/需求系统可以直接作为权威位置，结构化 handoff 与 Product Truth 按需使用，不能因工具名不同增加第二套业务真相。

根或模块 AGENTS.md、宿主规则、manifest 只负责工程约束、路由和引用；冲突回到有权来源解决。产品原型可以证明观察到的行为，不能由 Coding Agent 反推并确认缺失的业务政策。不要因为“交给研发”就自动增加可见评审态。

大任务按业务切片读取并保存有用检查点；小任务直接完成。调用者的真实权限、可用文件和执行环境优先于示例命令。任何部署、外部写入或发送都遵守用户的实际授权。

## 模型对照

固定任务、输入、权限、目标与验证环境。Skill 组加载目标版本的必要引用；纯模型组不加载目标 Skill。两组只产出当前任务所需产物，不因评测扩展功能，不跨组共享答案。

记录能实际取得的 provider、model_id、客户端版本、运行日期、设置、时间/token 与原始产物；缺失字段写未采集。品牌、用户俗称或共享密钥不构成模型版本证据。凭据仅通过受控运行环境提供，不进入提示词日志、需求材料或公开示例。

独立接收者按来源核实关键选择，比较错误、漏项、泛化、授权及人工负担；一次成功或模型相互赞同不证明稳定收益。评测完成不等于产品已经实现。

## 需求协作系统

外部工单可存稳定需求引用、标题/优先级、版本、依赖、评审/变更/验收链接。若它本身是既定权威系统，应引用其真实对象；不要另造同名状态台账。

开发、部署、业务签收是不同里程碑。外部“完成”不能反向伪造需求已验收。实现反馈要区分需求缺失、来源错误、投影漂移、实现偏差和环境问题，并回写实际负责的那一层。

需要汇总现有登记册时可手动执行 `scripts/validators/validate_requirement_register.py`，它只聚合已声明信息，不自动排期或分配人员。

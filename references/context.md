# 大任务、上下文与交接

摘要导航，不替代原文。

## 覆盖与执行

长任务、跨模块多轮变更或明确逐一核验时，先从用户要求和当前基线确定覆盖对象；不把模型生成的计划当唯一分母。可沿用现有计划、问题单或检查点，把任务、检查结果与证据关联在一处，不能另造一套业务规则。简单局部任务直接处理。

记录随任务而变：澄清检查影响当前选择的未知；编写/评审按接收者下一步需要拆模块；存量修改覆盖受影响规则与消费者；原型检查实际任务及状态；文档检查内容与版式。无须补齐未要求的生命周期阶段。每项写明来源与范围、可判定的完成条件、结论、产物版本和实际证据位置；条件可以是一句话，不强制模板或新文件。证据说明实际证明到入口可达、控件可操作、结果正确或重开保持中的哪一步，不强迫只读任务走保存流程。未验证不等于功能不存在，也不等于获准不做；“已有可用、空壳、需重建”等影响范围和排期的判断，须由相称的实现证据支撑。

区分待做、进行中、待验证、通过、失败、阻塞与有依据的不适用；执行顺序可按依赖调整或并行。脚本可枚举章节、页面和动作，不能批量填入语义“已读/通过”。读过后留关键理解、可区分的输入与预期或实际发现；检查失败不以任务已做替代关闭。追加范围或改变依赖时更新覆盖记录，受影响的旧通过转待复验，无关证据可有据复用。保留支撑当前结论、复验和恢复所需的证据，在现有记录中定位；过程文件不默认成为用户交付物，清理前核对恢复与追溯用途。

## 切片与恢复

恢复时回读当前文档、原型、来源、授权、证据及未决范围，说明未访问部分；旧生成器先核覆盖性。修订保留身份、取代关系和决定位置。小改不建检查点。

按角色路径读权限、状态、指标、恢复和验收；切片重组核对内容、修改回源。机器消费者才用多文件 Truth，Word/PDF 仍须渲染。

## 按需取领域与结构化资料

按有权来源选领域，知识包不代表授权或验收。只提取与本项目对象、地域、时期和任务相关的规则，就地标明依据，再写会区分错误实现的验收；不整段搬法规，也不把未核实资料变成默认政策。检索与切片工具见 [stages.md](stages.md)，估算不强制新增计划。

## 产品交付出口

用户要求挖清后交给开发或 Coding Agent 时，按其指定形式提供足够的业务约定和验收；只要其中一项的任务不强补另一项，小改仍回填原处。没有约定时，以接收者下一步所需选择最小产物；原型用于需要操作表现或明确要求的范围，不因“交开发”自动附加。模块验收统一表达业务预期，不另维护一份机器政策。

在原决定位置保留依据、关键取舍及复议条件；没有实质取舍不凑未选方案。就地或在交接末尾简述：哪些机制可由研发选择、哪些业务结果不可变、哪些未决分支本包尚不实现。说明原型中会被误抄的控件替代、种子身份/数据、浏览器存储和模拟请求；不要求另建绑定表。既有系统定位实际入口、对象和允许修改的模块，不平行搭新应用。

交付结论指出范围版本、原型入口、已验证层级和仍未证明的环境。静态通过不等于可上线。冷读范围按用户约定与接收风险选择，方法见[接收者冷读](specify.md#接收者冷读与行为验证)。要求逐模块独立可读时，对每个模块固定理解与缺口；少量代表任务或全文检索不能替代该覆盖。需猜关键业务选择时修原模块，不能降格为阅读建议后宣称交接通过。

## 给研发、测试与 Coding Agent 的交接

交给开发时，在现有入口简述确认版本、做与不做、未决操作限制，定位模块规则与验收。不复制细则、强制表格或重新审批；小改一句话即可。跨会话沿用，冲突只处理影响范围。

未决限制须可执行。例如已授权只做联机、离线提交未定：完成联机路径，不实现自动补交，独立工作可继续。多实体须定位身份与归并规则，名称不是身份。框架、锁机制及 API 路径留研发，不得改变业务结果；“结果未知”不能作为统一退路替业务选边。

原型区分产品依据、演示数据/身份、Mock 与评审工具。引用不可访问时附本范围规则、拒绝/恢复、验收、未决原文及版本；ID 不代替内容，已有包不重复。缺来源注明提供者，未知负责人不虚构。

接收者按约定范围核对是否把工具做成产品或改动归并；已有规则未执行时修实现。

仅在用户需要结构化机器交接时由 agent 生成 [handoff](templates/agent-handoff-manifest-template.yaml)，不是产品包的前置条件，用户不填 YAML。draft 可不完整；ready_for_implementation 只表示声明范围的产品规格可交接，核对实际范围、验收、引用和实施阻塞，不证明工程环境或上线就绪。已有工程基线则引用核对，尚未形成不强编。无留言不编造 handoffs；强追溯才用 execution-state。

选择结构化工作包才适用其 MOD/XCT/EDGE 与 qa_projection 合同。只有显式填写 implementation_step_refs 的包才校验其 STEP 卡八项：入口与责任、输入与权威源、处理与口径、守卫与状态、双结果、事件与责任交接、失败与恢复、追溯与验收；普通章节不因名称含 STEP 就被强制拆包。schema_version 5.3.0 是兼容协议号，不是 Skill 发布号。

`python scripts/ai_delivery_spec_cli.py gate --profile handoff --prd PRD.md --prototype app.html --manifest handoff.yaml`

引用环境、权限、凭据而非秘密；需求批准不代替操作授权。分别记录待同步、重验及依赖。反馈区分规格、来源、未知、投影、实现、技术及环境问题。例：“REQ-REPAIR／1.2；重试重复审计，见日志；实现偏差；修实现不改规则。”反馈保留版本、差异、证据、类别和处理方向，不授予变更权。

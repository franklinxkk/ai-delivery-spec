# 发布前实测

发布候选固定文件指纹，先修已证实问题，再对受影响行为复验。只重复因修改而失效的证据。版本号、运行包、源码快照和结果必须对应；未获授权不发布。

工程包可发布与效果主张成立分别判断。普通修复需运行包完整、受影响路径及反例验证、已知阻断闭合；不要求每次重做效果实验。有／无 Skill 收益仍按下述可比实验求证，工程通过不能推出减少返工。

## TRACE 自评

按 TRACE 五维组织下表的本地证据，先核对 [SkillHub 教程](https://skillhub.cn/tutorials#trace-evaluation) 当时是否仍提供测评说明。链接内容变化或细则不可得时，注明采用的已知维度与本地标尺，不能声称完成官方同等测评。这里是维护者自评，不是 SkillHub 重新评级，不复刻平台未公开的权重或实验室安全认证。

| 维度 | 本地观察 | 不能据此宣称 |
|---|---|---|
| T 可信任度 | 无关权限/外传、外部材料冒充指令、私有材料泄漏；离线核心能力和中英入口 | 静态抽查等于双实验室安全认证；所有国内网络都可用 |
| R 可靠性 | 实际入口、边界/反例、可操作错误、提取后运行包；新旧合同兼容 | 测试数量等于业务正确或任意语义可判定 |
| A 适用性 | 主流行业、中英输入、阶段与角色、微改及非需求负例；四快捷意图 | 模拟路由等于宿主实际隐式命中率 |
| C 规范性 | README 首屏复述和首次行动；按需导航、链接、模板和示例一致 | 模型表示愿意使用等于真人转化率 |
| E 有效性 | 新任务实际产物，接收者按模块复述/造数，跨产物一致与正反结果 | 合成案例等于真实项目返工减少或生产验收 |

先冻结适用义务及排除理由，分别报已检查覆盖率与已检查项满足率，失败、未查、不适用单列；没有检查时满足率为未计算。权重仅在事先有依据时使用，否则按项计数。关键未查不能被平均分掩盖。每维写观察、证据位置、问题处置和未测范围；需要评分时说明自定标尺，不能捏造官方分值。严重授权错误、关键规则冲突或关键流程不可用不能被平均分掩盖。已核实平台评分可用于介绍，但标明对应版本和核实日期。

## 模型冷启动对比

1. 选同一候选包和同一任务集。列明行业、阶段、角色、语言和交付类型的覆盖单元及正反预期，区分计划、产出、独立核对与通过，说明未覆盖组合。跨阶段结论须有同一需求贯穿交付、变更及验收的链，不能用独立短题拼成全流程。预先独立记录正确结果和重要错误，参与模型只拿任务/来源，不拿判分答案。
2. 每模型开无历史上下文会话；记录实际模型、输入、读取文件、命令和产物。先只给 README 首屏做用途/受众/下一步复述，再按任务读取 Skill。该环节叫首屏冷读模拟，不声称实测真人十秒。
3. 要求生成实际交付物并执行可用检查，不接受只描述“我会怎么做”。工具报错、配额或环境失败保留原记录，不算产品通过；反例须因目标约束被拒绝，其他报错不能冒充通过。修正前保留实际文件和日志，不只保留哈希；作者检查、独立接收和父代理补测分别归属。
4. 作者以外的接收方只看交付件，回答输入、守卫、结果、失败恢复和验收；必要时在实际浏览器操作。首次结果冻结，再给原始来源核对忠实性；若来源本属约定交付包就保留。修复另记，不把二次答案覆盖成首次全对。
5. 比较须猜业务选择、无依据扩展、关键漏项、跨产物冲突、可执行验收以及查找成本。不同模型同犯一错仍然是错。没有可靠计量时不报告耗时/token收益。

## 真人与项目效果

改生成/自检机制时，用普通任务口吻和原始材料做前后对照，不在任务里泄露边界清单或要求“专测某个缺陷”。两组用冻结技能、相同输入和环境，作者无历史讨论；真实缺决定可提出，接收者不要求它猜指定答案。首次作者交付前可自检，交付后立即封存文件；接收者先读约定交付包并冻结疑问，再给来源核对忠实性；随后给一次普通局部变更，检查旧行为和数据是否保留。

逐根因记录：首次交付违背已定规则、无授权扩展、关键遗漏/歧义、视觉或交互阻断、修订引入的回退、实际需用户澄清的业务选择。作者自检发现与独立接收后发现分开；环境失败单列。保留首份和修订份，比较同范围结果，少量案例只能说明该实验观察，不能换算普遍成功率、真人时间或返工收益。

有授权且有同口径记录时，记录真实项目首次交接后的澄清轮次、需求原因返工、实现缺陷及环境失败，保留分母和时期。无可比前测，不计算提升百分比。只有合成或模型数据时明确“该指标未测”，不因此杜撰真实业务数据，也不把日常任务升级成测评项目。

## 封板记录

记录本次修复、受影响回归、模型产物与接收结论、TRACE 观察、已知阻塞与非阻塞限制、运行包/源码指纹。核心未测或失败项仍影响交付时暂不封板；明确边界内证据充分即停止，不追求穷举所有组合。

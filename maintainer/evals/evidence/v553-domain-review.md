# 5.5.3 领域包与阶段反例复核

2026-10-11。基于本地提交 689beb5，复核全部 8 个内置领域包；本轮只维护 Skill，不更改真实交通项目的业务政策，不执行生产操作。许可继续为 MIT。

## 实际修正

| 领域 | 原来容易诱发的错误 | 已回填的边界 |
|---|---|---|
| 交通 | 所有三检必须先产生故障；每次检查都必须整改 | 增加正常完成分支；异常检查、维修事实和车辆放行权限分开；原证据不被维修结果覆盖 |
| CRM | 普通咨询关闭也一律逐单人审；多模块必建 Product Truth 和新字段编号 | 区分已授权普通自动处理与争议、合同及权益决定；共用业务事实即可，机器产物按消费者需要启用 |
| 教育 | 校园数据全部套同一标准；客观练习也逐题人审 | 核实教育标准排除范围与行业边界；自动练习反馈和正式成绩、学籍决定分开 |
| OA | 所有归档、索引动作逐次人审；所有电子签名必须 CA | 按动作、授权和采用方案判断；审批资格不等于执行发布；签署、归档转换、原始证据分别处理 |
| 医疗 | 同意作为唯一合法基础；全部研究固定走同名委员会；去标识化和伦理豁免混用 | 按目的核实合法基础和审查适用性；有依据的豁免保留机构责任，不能由 AI 自行批准；工作流和角色路径同步修订 |
| 数据产品 | 流水线配置与一次执行共用状态；反馈默认必须逐样本人审 | 配置版本、运行、重试证据分开；明确授权筛选、发布治理和独立评测集隔离 |
| AI 原生 | 只读回答也必须调工具并等待人审 | 区分直接回答、已授权有限动作和需审批动作；审批绑定具体内容/动作版本 |
| 多模态知识 | 撤回一个用途后删除全部合法证据，或反向以留存权继续广告使用 | 按用途、对象和派生范围传播撤权；独立留存依据不授权新用途 |

8 包同时注明：状态箭头、字段集合和 YAML 简写是设计示意，不能直接充当完整流程或可执行 Schema；必须根据实际范围补前置条件、正常/异常/恢复及历史版本影响。修正过时的“15 章节”计数，不把包的目录变成所有 PRD 的强制结构。模型自报信心不能伪装成校准概率。

另核实交通危货规范、CRM 官方路线图、数据产权登记、MCP 版本发布、C2PA 2.4 等领域锚点的证据类型；路线图不证明功能已可用，协议版本不替项目决定迁移，来源签名不证明陈述真实。新增 [医学研究伦理审查办法来源](https://www.szns.gov.cn/nsqsfj/gkmlpt/content/10/10510/mpost_10510979.html)并与发布机关说明交叉核对，明确豁免不是去掉姓名即可使用的通行证。

来源表保留原发布机关 URL，另记实际取得全文的地址、交叉证据和访问限制。共有 99 条登记来源通过元数据和刷新期限检查；这不表示本轮逐条重新阅读了 99 项全文或完成全法域法律审查。第二检索连接器曾出现网络传输失败，未计为独立验证成功；实际核验来自可访问的不同权威渠道。

## 反例覆盖与执行方式

当前六个阶段入口来自 references/stages.md；不发明新阶段，不把本轮维护工作变成每个客户任务的完整前置流程。

| 阶段入口 | 每个领域重点验证 |
|---|---|
| frame/explore | 目标和代理指标、证据与因果、备选方案、AI 或产品范围越权 |
| intake/clarify | 有效决定、来源权威、账号/数据映射、关键未知及阻塞范围 |
| specify | 正常与异常路径、对象/状态区别、计算口径、审批与自动执行、数据和事件结果 |
| prototype | 从实际操作验证配置、角色/直链/检索边界、失败及重试、Mock 与真实系统证据 |
| review/baseline | 来源适用性、版本、证据等级、协议/法律与实现选择、未证明的上线或验收声明 |
| change/acceptance | 旧对象与在途实例、消费者、撤权、迟到/重放、历史不可逆事实及验证失效 |

[完整反例集](../domain-stage-cases.md)由 [同源 JSON](../domain-stage-cases.json)生成，共 48 组、192 项：48 个合法对照、96 个明确错误、48 个需要有权决定的场景。题面中的项目政策仅在对应合成场景成立，不成为领域包默认规则。

三名独立代理只收到分配的题面和冻结的 Skill 指引，各自不见预期答案、其他代理输出及父任务评阅。分配为 72、72、48 项。首次输入和指引均留哈希；主代理逐项读完 192 条实际理由，检查是否解释机制、给出必要改法、保留合法行为并限制未知影响。

**首次判定与预设标签一致 190/192。两处分歧是题库混入了已知冲突，代理拒绝该错误是合理的：**

- traffic-01-D：题面已保留人类安全决定权，“平台自动决定营运”应直接修订；责任人未定是另外一个未知。
- medical-hospital-it-05-D：只有一家医院 SOP，却要求宣称全国通用，应先撤回无依据声明；是否扩院是另一个待确认范围。

保留原始输出和 [首次比较结果](domain-stage-verdicts-initial.json)，不回填成首次全对。[判据修正记录](domain-stage-adjudication.json)记录两个原条目、理由、新条目及前后哈希，可精确重建原题库。修订后的候选只保留真正的缺失决定，交由首轮未收到这些领域题目的代理审阅。12 项关联场景定向复测，判定 12/12 与预期一致，主代理逐条理由复核通过；见[原生复测输出](domain-stage-review-followup.json)与[复测比较](domain-stage-verdicts-followup.json)。这不是重新执行全部 192 项，也不与首轮次数相加宣称独立样本增长。

本轮识别测试侧问题而未发现仍未解决的输出行为错误，不等于证明任意场景都能正确处理。题目是明确、有限的合成候选审阅，尚未验证大段混乱材料中的自主发现、完整需求生成、真实浏览器操作、系统闭环或真人接收；也没有本轮纯模型对照，不能证明 Skill 相对增益。

## 可重复执行与证据边界

维护工具 maintainer/tools/eval_domain_stages.py 提供 prepare、render、score：
- prepare 只输出无预期答案的输入，不执行模型；
- render 从 JSON 展开 Markdown，避免人工维护两份规则；
- score 校验结果 ID 完整、无重复、判定合法且理由非空，并比较预设标签；它不判断理由是否正确。
- 原生代理结果在本目录 domain-stage-review-1/2/3.json；禁止拿本工具给出的数量充当领域语义验收。

新增 10 项 harness 回归覆盖漏答、重复、未知 ID、空理由、非法判定、错误判定不得计为通过、重复 JSON 键、输入哈希变化、盲题不泄露 oracle 及 CLI 缺输入。其作用是防止统计和证据失真，不能证明模型业务准确性。

[最终完整 release 记录](domain-stage-release.txt)退出 0，399 项 pytest 通过（59.40 秒）（包括上述 10 项，不再叠加）；8 包既有 19 项关键词合同夹具及 99 条来源登记检查通过。8 次实际 query-domain 调用返回对应政策切片，医疗新伦理来源可随切片检索。无浏览器产物变更，本轮没有重新运行浏览器。

领域成熟度继续保持 contract_tested；behavioral_eval 仅记 partial 并指向本次有限语义证据，专家、生产和客户验收均未升级。没有公开发布、全局安装或生成 ZIP。


维护复跑入口：`python maintainer/tools/eval_domain_stages.py prepare --output <隔离目录>`；模型各自只读取相应 blind 文件，输出 reviewer/results。全部当前题目需重跑时，再用 `score --responses <各组结果> --output <判定比较.json>`。原生结果与当前题库的两项差异已单独保留，不用当前题库冒充首次判据。

执行期间发现证据条目的状态枚举应为 current，有限行为覆盖另记 partial，已按现有Schema修正；曾一次未设置工作区 TEMP 导致沙箱临时目录清理失败，修正测试进程环境后复验，不放松产品检查。
